01

Design Tokens

Every value in the system — color, space, radius, duration — lives as a CSS variable. Nothing is hardcoded. This is what makes dark mode, theming, and future rebranding a one-file job.

Core principle
Tokens before values
Never write #FFD400 in a component. Write var(--solar). If a token doesn't exist for what you need, add it to the token file first — don't inline it.
foundational
Semantic over literal
Don't use --solar for a warning state just because the color looks right. Create --color-warning that points to --solar. The semantic name is what components consume.
All states in the same token file
Light mode, dark mode, high-contrast mode. Every token has a value for each. The token file is the single source of truth — not Figma, not memory.

Typography

Three roles. Three faces. Nothing else is permitted on the platform.

Typefaces
Geist Sans — UI & headings
Everything visible in the dashboard interface. All sizes from dashboard titles down to navigation labels. Never use bold above 600 weight — it looks heavy. 400 and 500 only in most contexts.
Inter — dense body & data text
Use Inter at 13px for dense information: table rows, metadata, description text. Its optical correction at small sizes outperforms Geist. Switch rules: table cells below 13px → Inter. Geist for everything ≥ 14px.
Geist Mono — data, IDs, code
Session IDs, charge point serial numbers, OCPP message IDs, API keys, kWh values, voltage readings, currency amounts, timestamps. Any value that benefits from tabular alignment. Set font-variant-numeric: tabular-nums alongside it.

✓ Do

Use sentence case in all UI labels, table headers, navigation, tooltips, toasts, and error messages. "Charge point settings" not "Charge Point Settings". Title case is for marketing pages only.

✗ Don't

Never use font-weight 700 or 800 in the dashboard. Never mix typefaces on the same label — if a number is Mono, its unit is also Mono. Don't exceed 3 distinct text colors on one card.

03

Color

Solar Yellow is a weapon. Use it surgically — one action per view. When yellow is everywhere, it means nothing.

⚡

The Yellow Rule: Solar Yellow (#FFD400) appears exactly once per viewport as a meaningful signal — the primary CTA button, the active nav item, or a critical alert. Never two yellows competing for attention on the same screen. This is what makes it land like a bolt every time.

Usage rules
Status color must never stand alone
A green dot means nothing to someone with deuteranopia. Always pair color with a text label or icon: ● Online, not just ●. This is a legal requirement in many markets and good engineering everywhere.
a11y required
Semantic colors are non-negotiable
Green = success / online. Red = error / offline / destructive. Amber = warning / charging / attention. Blue = info / link / focus. Never repurpose semantic colors for brand decoration. If Voltage Blue is used as a decorative accent in one place, it loses its meaning as an info signal everywhere else.
Dark mode is default, not an afterthought
The dashboard is dark-first. Light mode is available for operator preference. Every component is designed for dark first, then the light theme is tested. Not the other way. Use CSS color-scheme: dark on html.
APCA contrast for text
Use APCA (Advanced Perceptual Contrast Algorithm), not WCAG 2 ratio. --text-2 (#A0A0A0) on --bg-1 (#111) meets APCA Lc 60+. Target Lc 75+ for body text, Lc 45+ for large headings. Check at apcacontrast.com.

Spacing & Radius

An 8pt grid. Everything snaps to it. Infrastructure software earns its authority through precision, not decoration.

4px

8px
Label → value, badge internals
--sp-3
12px
Card → inner content, compact rows
--sp-4
16px
Default card padding, form fields
--sp-5
24px
Section gaps, generous card padding
--sp-6
32px
Between major sections
--sp-7
48px
Page-level section rhythm
--sp-8

Border radius
Radius scale: 3 → 6 → 10 → 16px
3px (--r-sm): tags, code pills, badges. 6px (--r-md): buttons, inputs, small cards. 10px (--r-lg): main cards, panels, modals. 16px (--r-xl): floating elements, demo frames. Never use 24px+ — it reads as consumer/mobile app, not infrastructure tooling.
Nested radii must be concentric
A button inside a card with --r-lg (10px) must use at most --r-md (6px). The inner element's radius is always ≤ outer radius. When a child is at the edge of a parent, their curves must align visually: inner_radius = outer_radius − gap.
05

Icons

Lucide React. One library. One stroke weight. One grid. No exceptions.

Rules
Lucide React is the only icon library
All icons from lucide-react. Never mix with FontAwesome, Material Icons, or custom SVGs in the same view. Stroke width is always 1.5 — Lucide's default. Never override stroke-width per icon.
lucide-react · strokeWidth=1.5
Icon sizes: 14 / 16 / 20 / 24px only
14px: inline with 12px text. 16px: standard UI icon (buttons, nav labels, table cells). 20px: section headers, prominent actions. 24px: hero illustrations, empty states. No other sizes.
Every icon-only button needs aria-label
A button with only an icon and no visible text must have aria-label="Refresh sessions". No exceptions. Test with a screen reader before shipping.
aria-label required
Kabisa-specific icon vocabulary
Maintain a documented mapping: Zap → charging/energy, MapPin → station location, Plug → connector/EVSE, Activity → session graph, Receipt → billing, Wifi → OCPP connection, Car → vehicle, AlertTriangle → charger fault. Consistent iconography builds operator muscle memory.
06

Buttons

Four variants. Each earns its place. One primary action per view — if everything is yellow, nothing is.

button variants
Rules
Exactly one primary button per view
A page or modal may have exactly one .btn-primary (Solar Yellow). If you find yourself wanting two, reconsider the IA — one action should be more important. Use .btn-secondary for the second.
Button labels are specific, not generic
Labels name the exact action and its object. Not "Submit", "Confirm", "OK". Yes: "Start charging session", "Save connector settings", "Generate invoice". When a dialog opens after clicking, the label ends with "…" (the ellipsis character &hellip;, never three dots).
no ambiguity
Loading state is always shown
Any async action shows a spinner + the verb in progressive form: "Saving…", "Connecting…", "Generating…". Keep the original label visible alongside the spinner — never replace the label with just a spinner. Disable the button during in-flight requests. Min loading state duration: 300ms (prevents flicker on fast networks).
300ms min
Destructive actions require confirmation
Any action that deletes, ends, or cannot be undone: show a confirmation dialog with the exact resource name. "End charging session CP-KGL-001?" with "End session" (danger) and "Keep charging" (secondary). Never just "Yes" / "No".
Hover lifts, active presses
:hover → translateY(-1px) + subtle shadow (1px only). :active → scale(0.98) + return to base. Duration: 120ms ease-out. This gives buttons physicality without looking like a Material Design throwback.
120ms ease-out
07

Forms & Inputs

A form is a conversation, not a questionnaire. Every field earns its presence or gets cut.

input states
Rules
Every input has a visible label
Placeholder text is not a label. Every <input> has an associated <label> element — either visible above the field or as a floating label. When the placeholder is the only label, screen reader users and users with cognitive impairments are lost the moment they start typing.
label required
Focus ring: Voltage Blue, 3px offset
box-shadow: 0 0 0 3px rgba(69,97,222,0.2) + border-color: var(--voltage-3). Never remove outline without replacing it. The focus ring is the keyboard user's cursor — removing it is like blinding a sighted user.
Errors appear inline, never in a toast
Validation errors live immediately below the offending field in --red. On form submission, scroll to and focus the first error automatically. Error message format: what happened + how to fix it. Not "Invalid value." Yes: "Enter a valid South African mobile number starting with +27 or 0."
Never block paste
Operators will paste charge point IDs, API keys, phone numbers. Blocking paste on any <input> or <textarea> is prohibited. Ever. Including OTP fields — let operators paste the code.
Enter submits the form
When the focused input is the only field, or the last field in a form, pressing Enter submits. In <textarea>, Enter inserts a newline; ⌘/Ctrl+Enter submits. Never make operators reach for a mouse to submit a simple form.
Unsaved changes are warned
If an admin is editing a tariff configuration and clicks away, show a browser-native beforeunload warning or a custom modal: "You have unsaved changes to Tariff T-001. Leave without saving?"

Status & Badges

Operators scan status at a glance. Every status is a dot + a text label. Color is never the only signal.

badge variants
Online Charging Offline Faulted OCPP 2.0.1 ⚡ Peak hour
Rules
Charging badge pulses, nothing else does
The amber dot on an active charging session pulses at 1.5s to signal live activity. This is the only animated status indicator in the system. Online, offline, and faulted dots are static — constant presence, no animation.
1.5s pulse · amber only
Badges are pill-shaped (border-radius: 99px)
The only elements in the system with full pill radius. They are categorically different from buttons (6px) and cards (10px). The round shape signals "state label" not "action".
09

Feedback & Toasts

Toasts are the voice of the system. They are calm, precise, and never apologize.

top-right toast examples
Session started — CP-KGL-002 · 7.4 kW · Token KBC-0042
Connector unreachable — Check OCPP connection on CP-KGL-005. View diagnostics →
Tariff updated — Weekend rate applied to 4 connectors. Undo
Rules
Toasts appear top-right, stack downward
Fixed position, 16px from the right edge, 16px from the top. New toasts appear at the top and push older ones down. Maximum 3 visible at once, older ones fade out. Use Sonner or a similar queue library configured to position="top-right". Never alert().
Success and info: 4s auto-dismiss. Errors: persistent
Successes auto-dismiss after 4 seconds. Errors stay until the operator dismisses them — an error that disappears before they can read the fix is worse than no feedback at all. Provide a link to the relevant resource in error toasts.
Toast copy: subject · what happened · action
Format: [Resource] — [what happened] — [optional action link]. "Invoice #1042 generated — RWF 12,400 — Download PDF →". Never start with "Error:" or "Success:" — the dot color carries that signal.
Optimistic updates for instant feel
When an action is likely to succeed (toggling a tariff, marking idle), update the UI immediately. If the server returns an error, roll back and show the toast. This is the difference between software that feels fast and software that feels like it's asking permission.
makes it feel fast
10

Data Tables

Tables are the core of an EV dashboard. They must be fast, dense, sortable, and keyboard-navigable. TanStack Table is the engine.

Rules
36px row height. Non-negotiable for dense data.
At 36px, an operator can scan 20 sessions without scrolling on a 1080p monitor. Vercel's activity tables, Cloudflare's request logs — all 36–38px rows. Anything taller is a concession to mobile habits in a desktop tool.
height: 36px
Numeric columns use Geist Mono + tabular-nums + right-align
Energy (kWh), duration, cost, power — all monospace, tabular, right-aligned. This is what makes large numbers scannable vertically. Mixing font styles in a table column is a mistake every generic dashboard makes.
text-align: right
Virtualize tables over 100 rows
Use virtua or TanStack Virtual for any list that can exceed 100 items. Sessions history, audit logs, billing records. Rendering 2,000 DOM nodes for a session history table is the first thing that will make a station manager call it "slow software".
virtua
Empty state is a next step, not a void
When a table has no rows: show the Kabisa icon + a specific message + one action. "No sessions on Kanombe Station 3 in the last 30 days. Check OCPP connection →" Not just "No data available."
All filters and sorts live in the URL
Use nuqs to sync table state (filters, sort, pagination, search) to URL params. An operator should be able to share a filtered session view with a colleague by copying the URL. This is table stakes for professional tooling.
nuqs · URL state

Animation

Motion is the language of live systems. The dashboard shows electricity flowing in real time. Every animation earns its place by communicating cause and effect — not by decorating.

⚡

The Kabisa animation philosophy: Our platform handles live electrical systems — sessions starting, power spiking, connectors switching state. Animation communicates that this is a live system, not a static report. Every animation should feel like watching actual electricity move. But restraint makes the meaningful animations land harder. One perfectly-timed entrance beats five scattered effects.

Micro
80–120ms
Button press, toggle switch, checkbox check. Must feel instant.
Standard
150–200ms
Hover states, badge transitions, row highlights, tooltip appear.
Transition
250–300ms
Panel open/close, tab switch, modal entrance, page skeleton reveal.
Orchestrated
400–600ms
Chart data load, stat card count-up, session list entrance with stagger.
Ambient
1.5–2s loop
Charging pulse on status dot. Nothing else loops.
Never
>600ms
Anything that makes the user wait to read content. Not animation — delay.
Easing curves
Snappy for UI state changes
cubic-bezier(0.25, 0.46, 0.45, 0.94) — fast exit, gentle deceleration. For dropdowns, tooltips, badge transitions, tab underlines.
--ease-snappy
Spring for items entering the view
cubic-bezier(0.34, 1.56, 0.64, 1) — slight overshoot gives physical weight. For modal entrance, drawer slide, stat cards appearing. Feels alive, not mechanical.
--ease-spring
Always honor prefers-reduced-motion
Wrap every animation in @media (prefers-reduced-motion: no-preference). Photosensitive users and users with vestibular disorders experience nausea or seizure from motion. This is not optional. The charging pulse on badges — remove the animation, keep the color.
required · no exceptions
Only animate transform and opacity
Never animate width, height, top, left, margin, or padding. These trigger browser layout recalculation on every frame — they make 120fps animations run at 20fps on real hardware. Transform and opacity are compositor-only: GPU-accelerated, zero reflow.
transform + opacity only
Stat cards count up on first load
Energy dispensed, total sessions, revenue — numbers count up from 0 to their value over 600ms using an ease-out curve when the dashboard first loads. Once loaded, numbers update instantly (no count-up on live updates). This is the "wow" moment. Use a requestAnimationFrame loop, not CSS — it needs to be interruptible.
wow moment
Live session graph ticks in real time
On the sessions page, the power draw graph appends a new data point every 30 seconds (or on OCPP MeterValues message). The line extends with a 200ms ease-out path animation — the chart visibly breathes. Not a full re-render — an SVG path extension.
live electricity
Stagger list entrances
When a table or card grid loads, stagger the row/card opacity + translateY entrance: 30ms delay between each item, capped at 8 items (items 9+ appear instantly). This creates the sense of a list assembling itself — the dashboard feels alive without being chaotic.
30ms stagger · 8 max
12

Interactions

Interactions are accessible by default and fast for power users. Core desktop flows work with keyboard navigation, while touch-first mobile flows provide equivalent accessible controls.

Keyboard & Navigation
Keyboard accessibility for core desktop flows
Core dashboard flows, starting a session remotely, editing a tariff, viewing diagnostics, must be completable with keyboard navigation. Support Tab, Shift+Tab, Arrow keys, Enter, and Escape with visible focus states. Mouse and touch are welcome, but never required for critical desktop work. For map-heavy or mobile-first interactions, provide an equivalent list, control, or accessible fallback.
WAI-ARIA
State lives in the URL. Always.
Filters, pagination, selected tab, expanded panel, modal open — if it's a state the operator cares about, it lives in the URL via nuqs. Share, Refresh, Back, Forward must all work exactly as expected. This is what separates Kabisa from local tools with no memory.
share / refresh / back
⌘K command palette on every page
Cmd/Ctrl+K opens a global command palette (cmdk). Operators can navigate to any station, start a session on a connector, pull up an invoice, or change a tariff without hunting through the sidebar. Index everything: stations, charge points, recent sessions, settings pages. This is the shortcut that makes power users love the product.
power user feature
Focus rings: never hidden, always Voltage Blue
Use :focus-visible (not :focus) to avoid showing rings on mouse click while showing them on keyboard navigation. The ring is box-shadow: 0 0 0 3px rgba(69,97,222,0.25) — visible, not intrusive.
:focus-visible
Links use <a>, never <div onClick>
Navigation always uses <a href> or Next.js <Link>. This gives Cmd+Click (open in new tab), middle-click, right-click context menu, and screen reader navigation for free. A <div onClick> that navigates is a broken link.
Scroll position persists on Back navigation
If an operator scrolls to the 40th session in a list, clicks into it, then presses Back, they return to where they were — not the top of the list. Implement with ScrollRestoration in the router or manual sessionStorage scroll position tracking.

Sessions Page

This is our showcase screen — the one that makes operators say "I've never seen this in East Africa." It is the most data-rich, most live, most customizable page in the platform.

⚡

Design goal: An operator opens a live session and sees electricity moving — power draw graphing in real time, SoC climbing, session cost ticking upward. They feel in control. This screen should feel closer to a Bloomberg terminal than a spreadsheet. Every data point serves a decision.

Data displayed per session
Live metrics (update every 30s or on MeterValues)
Power draw (kW) · Voltage (V) · Current (A) · Energy dispensed (kWh) · Session cost (RWF) · Duration · State of Charge if reported by vehicle. All values displayed in Geist Mono with tabular-nums. New readings animate in with a 100ms fade.
live data
Power draw graph: always visible, always live
The session detail view always shows a power (kW) over time chart as the primary visual. It uses Recharts with Voltage Blue as the line color and a subtle fill gradient. The chart extends rightward in real time. On hover, a crosshair tooltip shows exact values at that timestamp. This is the WOW moment — operators see electricity as a living signal.
signature feature
Admin-configurable visible columns and panels
Each operator account stores a sessionViewConfig preference: which metric cards are pinned, which graph types are shown (kW, V, A, SoC), whether the OCPP message log is expanded by default. Saved server-side per user. The gear icon top-right opens a "Customize view" panel.

14

Admin Customization

Operators own their view. The platform remembers how each operator works and surfaces what matters to them.

What operators can control
Dashboard metric cards — pin / unpin / reorder
The top stats row is operator-configurable. Available metrics: Total kWh today, Active sessions, Revenue (RWF), Faulted connectors, Average session duration, Top station by usage. Drag to reorder, click × to unpin, + to add. State saved server-side to their account.
drag to customize
Session detail view — choose visible panels
Each operator saves which panels are visible in session detail: Power graph, Voltage graph, Current graph, SoC display, OCPP log, Cost breakdown. Technical operators see OCPP logs; billing admins see cost breakdown. One interface, multiple personas.
Column visibility in all tables
Every data table has a Columns button that opens a checklist of available columns. The visible set is saved per table per user. Default columns are set per role. When an operator hides a column, it's hidden on their next login too.
Role-based default views
Three role defaults: Station Manager (operational focus: uptime, faults, sessions), Billing Admin (financial focus: revenue, invoices, payment status), Technical (deep focus: OCPP logs, diagnostics, firmware). Roles determine default column sets and dashboard cards — not what they can access.
Time zone and locale preference
Operators in Kigali see CAT (UTC+2). Future operators in Nairobi (EAT, UTC+3) or Kinshasa (WAT, UTC+1) see their local time. Dates use locale-aware formatting via Intl.DateTimeFormat. Currency uses Intl.NumberFormat. No hardcoded "RWF" strings in components.

Copywriting

Every word is a design decision. Kabisa's voice is confident, specific, and never apologizes. It explains without condescending.

The deployment was successful.
→
Session started on CP-KGL-002.
Error occurred. Please try again.
→
CP-KGL-005 didn't respond. Check its OCPP connection in Diagnostics →
Are you sure you want to continue?
→
End this session on CP-KGL-002? The driver will be billed RWF 4,230.
No data available.
→
No sessions at Kanombe Station in the last 7 days. Check if connectors are online →
Voice rules
Sentence case everywhere in the UI
Navigation, buttons, table headers, labels, tooltips, modals, toasts. All sentence case. "Charge point settings" not "Charge Point Settings". Exception: proper nouns (Kabisa, OCPP, MoMo), abbreviations (kWh, RWF, SoC), and page headings on marketing pages.
Errors name the resource and give the fix
Never "Something went wrong." Always: what failed (the resource), why (specific cause if known), how to fix it (link or action). "Invoice #1042 couldn't be generated — the billing period has no sessions. Add sessions or change the period."
Numbers use numerals, units have a non-breaking space
"8 sessions", not "eight sessions". "7.4 kW", not "7.4kW". The space prevents "7.4" and "kW" from splitting across lines. Use &nbsp; or the Unicode non-breaking space \u00A0 between number and unit.
7.4 kW · 240 V
Active voice for actions, passive for states
Buttons and labels are active: "Start session", "Generate invoice", "Connect charge point". State descriptions are passive: "Session started", "Invoice generated", "Connector online". The verb form signals whether something is happening or has happened.
Brand names are protected from translation
Wrap brand names, OCPP terms, and technical identifiers with translate="no" to prevent browser auto-translate from mangling them. <span translate="no">OCPP</span>, <span translate="no">MoMo</span>.
16

Accessibility

The platform must work for every operator, regardless of how they navigate. This is ethics, not a checkbox.

⚠

Minimum bar: WCAG 2.1 AA. Target bar: WCAG 2.1 AAA for critical dashboard views. Use APCA for contrast calculations (more accurate than WCAG 2 ratio). Test core desktop flows with keyboard navigation, then with VoiceOver on macOS, before marking any feature complete.

Non-negotiable requirements
Semantic HTML before ARIA
Use <button> not <div role="button">. Use <table> for tabular data not CSS grids with roles. ARIA is a polyfill for when native semantics can't do the job — not a replacement for correct HTML.
aria-live for async updates
Session status changes, new toast messages, real-time metric updates — all announced via aria-live="polite". Live charging power values use aria-live="off" (they update too frequently to announce every change).
aria-live="polite"
Skip to content link
A visually hidden "Skip to main content" link appears on :focus at the top of every page. It jumps focus to <main>. This is the first thing a screen reader user or keyboard user encounters — make it work.
Chart accessibility
Every chart has an accessible table alternative, hidden visually but readable by screen readers. Use role="img" + aria-label on the chart container describing what the chart shows. The power draw chart: aria-label="Power draw over session duration. Current: 7.2 kW."
17

Performance

The dashboard will be used on 4G connections in Rwanda. It must be fast on those connections, not just on a Nairobi office fiber line.

Budgets & targets
Network targets
POST/PATCH/DELETE: <500ms. Dashboard initial load (LCP): <2.5s on 4G. Table data fetch: <800ms for 100 rows. Real-time updates: OCPP MeterValues displayed within 200ms of receipt. These are not suggestions — add performance budgets to CI.
<500ms / <2.5s LCP
Skeleton screens, not spinners
Dashboard cards, tables, and charts use skeleton loaders that match the exact layout of the loaded content — preventing layout shift when data arrives. Spinners are for actions (button loading state), not page loads. Minimum skeleton visible time: 300ms to prevent flicker on fast connections.
no layout shift
Virtualize everything over 100 rows
Session history, billing records, audit logs, OCPP message logs. Use virtua (faster than react-window). Rendering 500+ DOM nodes for a session table is the #1 performance killer in operator dashboards. Measure with React Scan before shipping.
virtua
Font subsetting
Ship only the Unicode ranges in use. Geist Sans: Latin + Latin Extended. Geist Mono: Latin only (no extended characters in data values). Use unicode-range in the @font-face declaration. Unsubsetted Inter is 1.2MB — the subset for this use case is ~80KB.

Our Standard

The question we ask before shipping anything.

⚡

The Kabisa bar: Would a station manager in Kigali, opening this screen on a 4G connection at 7am before the morning rush, feel in control? Would they see exactly what they need, trust what they're looking at, and know exactly what to do next? If the answer is anything less than an immediate yes — it's not done.

The 5 questions before every ship
1. Can I complete critical desktop flows with a keyboard?
Put the mouse aside for core dashboard tasks. Open the feature, tab through it, trigger actions with Enter, escape dialogs with Escape, and confirm focus is always visible. If a critical desktop task gets stuck, it is not shipped. For mobile or map-heavy tasks, verify the accessible fallback instead.
2. Is every state designed?
Loading, empty, sparse, dense, error, success. Open the network tab. Add network throttle. Check that every state is explicit and guides the next action.
3. Does the URL reflect the state?
Apply filters. Sort a table. Open a modal. Copy the URL. Open it in a new tab. Did it restore exactly?
4. Is there anything that could surprise or confuse an operator?
Show it to someone unfamiliar with the feature. Watch where they hesitate, misread, or miss the action. Those are the bugs.
5. Would you be proud to show this to Google or Wise?
Not as a startup. As an equal. The Kabisa platform should be the thing that proves East Africa builds world-class infrastructure software. Every screen is a statement.
